## Phase Goal

**As a** signed-in researcher, **I want to** create, save and edit my own profile (career stage, mentoring toggles, give/need fields) and see an AI-suggested methods badge I can override, **so that** Findings has what it needs to match me with the right collaborators and mentors.

This plan's slice: the profile form and read-only view work end to end against the real database, with every field, the stage-driven mentoring toggles and the Home call-to-action. The methods badge is added in 02-03 on the AI client built in parallel by 02-02.

## Artifacts this phase produces

This plan: `findings/core/constants.py`, `findings/repos/profiles.py` (PROFILE_COLUMNS, update_own), `findings/services/profile_service.py`, `ui/profile_view.py`, `views/profile.py`, Home CTA in `views/home.py`, My profile nav entry in `app.py`, live checks D11-D13 in `scripts/check_live.py`, `tests/fakes_profiles.py` and four test files.
Whole phase: the above plus `findings/ai/` (client.py, prompts.py, methods.py), `Settings.gemini_api_key`, the Phase 2 section of `supabase/schema.sql` (methods_hash, methods_reason), `scripts/check_gemini.py`, the methods badge and override control, and the second-account RLS probe P1-P9 in `scripts/check_live.py`.

## Planner Assumptions

- PA2-01: The widget keys listed in `FORM_KEYS` (f_name, f_stage, f_institution, f_education, f_experience, f_bio, f_looking_for, f_interests, f_skills, f_offers, f_needs, f_contrib, f_learn, f_seeking, f_open) are a public contract: Phase 7 autofill pre-fills exactly these keys.
- PA2-02: `get_own_profile` defaults to the full `PROFILE_COLUMNS` (shared contract: later phases call `get_own_profile(sb, user_id)` and need the whole row). `PROFILE_SUMMARY_COLUMNS` stays exported.
- PA2-03: `save_profile` returns the saved row as a dict. 02-03 adds one extra non-column key, `ai_status`.
- PA2-04: The AI layer is left out of the tracer on purpose, so wave 1 can build it in parallel (02-02). `save_profile` already does its core write first, so 02-03 adds the methods write after it without changing the architecture.
- PA2-05: After a save that leaves the profile incomplete, the page stays in edit mode and lists what is missing. A complete save switches to view mode.
- The edge items EC-01 to EC-09 in `must_haves.assumptions` come from the spec-less probe. They are the planner's chosen behaviour and the user has not confirmed them. Each one is implemented and tested below.
