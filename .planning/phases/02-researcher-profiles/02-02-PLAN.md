## Phase Goal

**As a** signed-in researcher, **I want to** create, save and edit my own profile (career stage, mentoring toggles, give/need fields) and see an AI-suggested methods badge I can override, **so that** Findings has what it needs to match me with the right collaborators and mentors.

This plan's slice: the shared, streamlit-free Gemini client that this phase and Phases 3, 4, 6 and 7 reuse, the methods classifier built on it, the two bookkeeping columns, and a live smoke script. It runs in parallel with 02-01. 02-03 wires it into Save and the badge.

## Planner Assumptions

- PA2-06 (shared contract): `generate_structured(prompt, schema, *, parts=None)` is positional-compatible with the cross-phase contract. The extra keywords `system`, `client` and `models` are optional. With no `client` it uses a module default: the key given to `configure(api_key)` (app.py calls this in 02-03), or the GEMINI_API_KEY environment variable if `configure` was never called (for scripts). `configure(None)` disables the AI deliberately, even when the variable is set.
- PA2-07 (shared contract over RESEARCH): the schema change goes in a new section appended at the end of `supabase/schema.sql` (an additive grant on the two new columns), not as an in-place edit of the section-8 grant list. The contract says later phases append and never rewrite earlier sections. The section has to stay after section 8, because section 8 re-runs `revoke update ... ; grant update (...)` on every apply.
- PA2-08: `MethodsSuggestion` lives in `findings/ai/methods.py`, and there is no separate schemas module (fewer files). Later phases define their own response models next to their own features.
- PA2-09: there are no SDK retries (`HttpRetryOptions` is unset), so the model chain is the retry. Each request times out after 15 s, so the worst case is about 30 s inside the Save spinner. The core profile write has already succeeded by then.
