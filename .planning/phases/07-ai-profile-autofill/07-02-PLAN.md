<objective>
PDF CV autofill on the same panel. The researcher uploads a PDF of at most 5 MB and 10 pages. The app checks it with pypdf (size, header, parse, encryption, page count, text layer) before any Gemini call, then sends it inline with `types.Part.from_bytes`. The returned ProfileDraft goes through the same sanitise and merge path as text, so the form fills in and nothing is saved until Save. The PDF is never stored.

Output: the pypdf pin, pre-flight checks, inline PDF call, uploader UI, tests, a sample PDF, and a live smoke `--pdf`.

findings/services/autofill.py:
- Constants (per D-08):
  - `MAX_PDF_BYTES = 5 * 1024 * 1024`
  - `MAX_PDF_PAGES = 10`
- Fixed messages, each a user-safe string:
  - MSG_PDF_NONE: "Choose a PDF first."
  - MSG_PDF_EMPTY: "That file is empty. Upload your CV as a PDF or paste the text instead."
  - MSG_PDF_TOO_LARGE: "That PDF is larger than 5 MB. Upload a smaller file or paste the text instead."
  - MSG_PDF_UNREADABLE: "That file isn't a readable PDF. Upload a PDF or paste the text instead."
  - MSG_PDF_ENCRYPTED: "That PDF is password-protected. Remove the password or paste the text instead."
  - MSG_PDF_TOO_MANY_PAGES: "That PDF has more than 10 pages. Upload a shorter CV or paste the relevant part instead."
  - MSG_PDF_UNAVAILABLE: "PDF autofill isn't available right now. Paste the text instead."
  - MSG_NOTHING_FOUND_PDF: "Couldn't find profile details in that PDF. Try another file or paste the text instead."
- Frozen dataclass `PdfInfo(pages: int, has_text: bool)`.
- `preflight_pdf(data: bytes) -> PdfInfo` runs these checks in order, and each failure raises AutofillError with the matching message:
  1. Empty data.
  2. Size over MAX_PDF_BYTES, checked before any parsing.
  3. The "%PDF-" signature must occur within the first 1024 bytes, otherwise UNREADABLE.
  4. Import pypdf lazily inside the function. An ImportError gives MSG_PDF_UNAVAILABLE.
  5. `pypdf.PdfReader(io.BytesIO(data))` inside a broad try. Any exception gives UNREADABLE, logging the type name only.
  6. `reader.is_encrypted` gives ENCRYPTED. This is checked before touching pages, and the app never decrypts.
  7. `len(reader.pages)` inside a try. An exception or 0 pages gives UNREADABLE; more than MAX_PDF_PAGES gives TOO_MANY_PAGES.
  8. `has_text` is `bool(reader.pages[0].extract_text().strip())`, first page only, inside a try that falls back to False.
  pypdf output is used only for these checks and is never sent to Gemini (per D-13).
- `autofill_from_pdf(data: bytes) -> ProfileDraft`:
  - Always calls preflight_pdf itself and never trusts the caller.
  - Then calls `_generate(build_autofill_prompt(None), parts=[pdf_part(data)])` and `sanitize_draft`.
  - If the sanitised draft is empty, raises MSG_NOTHING_FOUND_PDF.
- Do not keep, cache or log the bytes (per D-09).
